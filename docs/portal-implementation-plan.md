# 员工 Portal 第一版实施方案

日期：2026-09-14

技术约束：用户要求尽量轻量，并明确不熟悉 PHP。新建方案采用 JavaScript 和 Node.js，减少运行服务、框架和构建步骤。用户已确认数据库部署在独立服务器的 Docker 上，并提供容器列表。服务器另有正在使用的 React IT Portal；是否扩展该项目或另建项目，待用户选择。

## 1. 产品目标

建立一个独立的员工网站导航门户。员工从同一个首页找到并打开公司网站；管理员在后台维护网站目录、分类和门户内容，日常更新不需要修改代码或重新部署。

Portal 的核心流程：

> 管理员新增网站 → 填写名称、地址、图标和简介 → 预览 → 发布 → 员工首页展示。

IT HelpDesk 继续承担工单、审批、通知和邮件等业务。Portal 只提供网站入口，第一版不读取这些业务数据。

## 3. 第一版范围

### 员工首页

- 公司 Logo、门户标题、简短首页说明。
- 网站卡片：图标、名称、简介、分类、访问按钮。
- 按名称、简介和管理员填写的关键词搜索；按分类筛选。
- 按管理员设置的顺序展示。
- 默认新标签页打开目标网站，保留门户页面。
- 支持手机、桌面以及中文、英文切换；缺失的翻译回退到已填写语言。
- 浅色、深色模式切换；未选择时跟随系统设置，选择后在该浏览器中记住。
- 没有网站、没有搜索结果、网络失败时提供相应状态。

### 网站管理

- 列表、新增、编辑、预览。
- 上传图标，或选择预置图标。
- 草稿、已发布、已隐藏、占位四种状态。
- 拖动排序，同时提供上移/下移按钮，支持键盘和手机操作。
- 上架、隐藏与重新上架。
- 首页从数据库读取目录，更新不依赖前端重新打包。

### 分类与门户设置

- 分类名称、英文名称、排序；允许暂时不分类。
- 修改门户标题、英文标题、Logo、首页说明和英文说明。
- 固定布局，编辑内容与顺序。

### 管理员账号

- 登录、退出；所有管理页面和写入接口都验证管理员身份。
- 首个管理员由部署命令创建，密码通过隐藏输入填写。
- 提供受服务器权限保护的管理员创建/密码重置命令，不依赖邮件服务。
- 第一版不开放员工注册，也不自动把首个访问者设为管理员。

### 后续按需考虑

收藏、最近使用、部门专属目录、管理员账号管理页面和统一登录可在实际需求出现后增加。

跨系统待办、统一通知、工单状态展示、网页内嵌和自由页面搭建不属于本次实现范围。

## 4. 页面与交互

| 地址 | 页面 | 主要操作 |
| --- | --- | --- |
| `/` | 员工首页 | 搜索、分类、打开网站、切换语言 |
| `/admin/login` | 管理员登录 | 邮箱、密码登录 |
| `/admin/sites` | 网站管理 | 搜索、按状态筛选、排序、新增、编辑、隐藏/上架 |
| `/admin/sites/new` | 新增网站 | 填写信息、预览、保存草稿或发布 |
| `/admin/sites/:id/edit` | 编辑网站 | 修改信息、预览、保存 |
| `/admin/categories` | 分类管理 | 新增、编辑、排序、删除空分类 |
| `/admin/settings` | 门户设置 | 修改标题、说明和 Logo，预览并保存 |

新增网站表单：

| 字段 | 行为 |
| --- | --- |
| 名称 / 英文名称 | 至少填写一种语言；员工选择另一语言时使用回退内容 |
| 简介 / 英文简介 | 可选，限制长度，以纯文本显示 |
| 网站地址 | 发布真实网站前必填；支持 HTTP/HTTPS 内网或公网地址 |
| 图标 | 预置图标或上传图片；无图标时使用默认样式 |
| 分类 | 可选 |
| 搜索关键词 | 可填“报修、电脑、网络”等员工常用词 |
| 打开方式 | 默认新标签页，可选当前标签页 |
| 状态 | 草稿、发布、隐藏或占位 |

保存语义：

1. **新网站保存草稿**：只在后台可见。
2. **预览**：在编辑页面显示卡片效果，不改变员工首页。
3. **发布**：校验字段后保存，员工下一次加载首页即可看到。
4. **编辑已发布网站**：明确使用“保存并更新首页”；预览期间员工仍看到已保存内容。
5. **隐藏**：员工目录接口也不返回该网站；后台保留记录，可重新上架。
6. **占位**：首页显示卡片及“待补充”状态，访问按钮禁用；填入有效地址并发布后成为正常入口。

员工刷新或重新打开首页时取得最新目录。第一版不引入实时推送。

## 5. 数据设计

数据库与 HelpDesk 分离，核心实体如下。

### `admins`

`id`、`name`、`email`（唯一）、`password`（哈希）、`active`、创建/更新时间。

管理员账号单独建模；停用后已有会话也失去管理权限。

### `sites`

`id`、`name`、`name_en`、`description`、`description_en`、`url`（可空）、`icon_key`、`icon_path`、`category_id`（可空）、`keywords`、`open_in_new_tab`、`status`、`sort_order`、`created_by`、`updated_by`、创建/更新时间。

- `status` 枚举：`draft`、`published`、`hidden`、`placeholder`。
- 员工目录只返回 `published` 和 `placeholder`。
- `published` 必须具备有效地址；`placeholder` 不提供可点击链接。
- 排序按 `sort_order`、`id` 稳定排列；批量排序在事务中保存。

### `categories`

`id`、`name`、`name_en`、`sort_order`、创建/更新时间。

仍被网站使用的分类不能直接删除，后台提示先移动相关网站。

### `portal_settings`

单条配置记录：门户中英文名称、中英文首页说明、Logo 路径、默认语言、最后修改人和更新时间。

管理员会话使用独立的 `sessions` 表持久化保存，包含到期时间。图片存储在 Portal 自己的持久化目录中，数据库仅保存相对路径。

## 6. 技术实现

以下是另建项目时的方案。若用户选择扩展现有 Portal，先获取其源码及配置，保留 React 页面并围绕内容管理补齐能力，不据此新建方案重写现有项目。

新建时采用单个 JavaScript 项目，员工首页、管理后台及接口由同一个 Node.js 服务提供。设计以少量管理员维护网站目录、员工主要浏览为前提。

| 部分 | 选择 | 理由 |
| --- | --- | --- |
| 页面 | HTML、CSS、原生 JavaScript | 页面数量少，搜索、表单预览和排序只需要少量浏览器交互 |
| 页面模板 | EJS | 服务端用 JavaScript 把数据库内容填入 HTML，共用页头、导航和网站卡片模板 |
| 服务端 | Node.js LTS + Express 5 | 前后端使用同一种语言，一个服务承载页面、登录和目录管理 |
| 数据库 | 优先复用服务器上的 PostgreSQL；具体实例待选 | 减少新增运维服务，同时为 Portal 隔离数据和访问账号 |
| 数据访问 | 最终所选数据库的 Node.js 驱动 + 参数化 SQL | 表结构与查询简单，使用编号 SQL 迁移；第一版只实现选定的一种数据库 |
| 测试 | Node.js 自带测试运行器 + HTTP/浏览器验证 | 验证真实权限、发布和持久化行为 |

页面直接由服务端渲染，基础浏览和表单提交采用普通网页请求；浏览器 JavaScript 增强预览、排序和筛选。模板只来自项目代码，管理员填写的文本按转义规则输出。

第一版没有单独的前端开发服务器或前端打包步骤。使用一个 `package.json` 和依赖锁文件；Node.js 与第三方依赖在开发时选用受支持版本并固定。

建议目录：

```text
employee-portal/
├── src/
│   ├── server.js            启动入口
│   ├── app.js               Express 应用
│   ├── routes/              员工页、后台页面与管理接口
│   ├── services/            数据访问、会话、网站发布逻辑
│   └── middleware/          登录校验、字段校验与错误处理
├── views/                   EJS 页面和共用模板
├── public/                  CSS、浏览器 JavaScript、预置图标
├── migrations/              编号 SQL 迁移
├── scripts/                 管理员创建、密码重置、备份命令
├── tests/                   权限、发布与持久化测试
├── data/                    上传及本地运行数据；SQLite 备选文件，不提交 Git
├── .env.example
├── package.json
├── package-lock.json
└── README.md
```

数据库确定后，开发、测试与生产采用同一种引擎；自动化测试使用隔离的临时数据库。迁移用版本表记录已执行步骤，目录发布和排序使用事务。若复用 PostgreSQL 或 MySQL/MariaDB，为 Portal 创建专属数据库和限制到该库的账号，测试不访问现有业务数据库。

新建项目部署为一个 Node.js 服务和一个持久化上传目录，连接现有数据库。按单实例运行，由部署环境的进程管理器负责开机启动和异常重启，HTTPS 接入现有反向代理。如果在服务器 Docker 中部署 Portal，则增加一个独立应用容器，通过所需容器网络连接数据库，不重复部署数据库容器。复用现有 Portal 时，先核对其现有构建和部署流程。

如果没有合适的现有服务，SQLite 备选可把数据保存在 Portal 服务器本地持久化磁盘，不需要独立数据库服务。

规划提供 `npm ci` 安装、`npm start` 启动、`npm test` 测试，以及管理员管理命令。交付说明包含所选数据库的一致性备份和恢复操作，同时覆盖上传目录；应用更新保留运行数据。

管理接口使用成熟的 Express 服务端会话中间件和适合所选数据库的持久化会话存储：登录后更新会话 ID，退出后使会话失效，写入操作有 CSRF 校验，登录有失败频率限制。Cookie 名称与 HelpDesk 分离，使用 HttpOnly、SameSite，生产 HTTPS 下启用 Secure；数据库保存密码哈希。

后端执行管理权限与发布状态校验；前端的菜单显示和按钮禁用仅用于交互反馈。网址限制为 HTTP/HTTPS；名称及说明不解析自定义 HTML；上传图标允许经过校验的 PNG/JPEG/WebP，初始大小限制 2 MB。

## 7. 接口约定

| 接口 | 权限与用途 |
| --- | --- |
| `GET /api/portal` | 员工可读；一次返回门户设置、可见分类和已发布/占位网站 |
| `POST /admin/login` | 登录；CSRF 与登录频率限制 |
| `POST /admin/logout` | 已登录管理员退出 |
| `GET /api/admin/me` | 获取当前管理员，未登录返回 401 |
| `GET/POST /api/admin/sites` | 管理员读取全部状态或新增网站 |
| `GET/PATCH /api/admin/sites/:id` | 管理员读取、编辑及修改发布状态 |
| `PUT /api/admin/sites/order` | 管理员批量保存网站顺序 |
| `GET/POST /api/admin/categories` | 管理员读取、新增分类 |
| `PATCH/DELETE /api/admin/categories/:id` | 管理员编辑或删除空分类 |
| `PUT /api/admin/categories/order` | 管理员保存分类顺序 |
| `GET/PATCH /api/admin/settings` | 管理员读取、修改门户设置 |
| `POST /api/admin/media` | 管理员上传图标或 Logo |

所有写入接口都接受后端字段校验。返回给员工的目录不含管理员信息及草稿/隐藏内容。接口统一返回清晰的字段错误、未登录状态及保存失败信息。

普通表单提交与 JSON 接口复用同一业务服务和权限检查。页面成功提示以数据库写入成功为准，保存失败时保留已填写信息。

## 10. 验收用例

1. 管理员新增一个网站并发布；新的员工浏览器会话能看到并打开它。
2. 修改名称、简介和地址；刷新员工首页后展示修改结果，无需重新构建或部署。
3. 隐藏网站后，员工目录接口与首页都不再包含它；重新上架后恢复。
4. 调整排序后刷新页面，顺序保持一致；移动端也能通过上移/下移完成排序。
5. 草稿仅后台可见；占位卡片可见但无法跳转；没有有效地址时不能发布为真实网站。
6. 未登录、退出后以及已停用管理员均不能写入目录、上传图片或修改门户设置。
7. 搜索支持名称、简介和关键词；语言切换及翻译回退正常；手机宽度不发生横向溢出。
8. 无效网址和无效图片得到明确错误，已有内容不被错误提交覆盖。
9. 重启 Portal 后，目录、设置、排序及图片仍然存在。
10. Portal 的运行和测试不修改 HelpDesk 的业务数据、邮件配置或部署配置。
11. 在新的临时数据目录恢复一次备份，验证网站目录、设置、排序和图片完整。

自动化测试集中覆盖管理权限、状态过滤、发布校验、持久化、排序与上传校验；浏览器验证重点覆盖“新增 → 发布 → 员工首页 → 编辑 → 隐藏/恢复”。

## 11. 技术依据

- 用户最新要求：技术栈尽量轻量，避免需要学习和维护 PHP。
- 用户提供的 `appserver` Docker 容器列表，以及对现有 `http://192.168.2.213:8095/` 页面和已引用的静态资源的只读检查。
- [Express 安装文档](https://expressjs.com/en/starter/installing/)：使用 Node.js 和 npm 安装并运行服务。
- [EJS 官方文档](https://ejs.co/)：使用普通 JavaScript 生成 HTML，支持 Express 视图及模板复用。
- [SQLite 适用场景](https://www.sqlite.org/whentouse.html)：适用于很多网站与应用服务端；需要大量并发写入或多服务器共享数据库时再评估客户端/服务端数据库。
